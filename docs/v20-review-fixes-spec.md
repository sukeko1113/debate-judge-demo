## 3. 判定理由に関わる修正（優先順）

### 3.1 保留2件の組合せ感度と、単独感度の固定条件 【最優先】

**問題。** 判定の場面に出る「この値が5以下なら判定は逆転する」は、もう一方の保留（否定・発生可能性）を暫定4に固定したときだけ成り立つ。両方を同時に動かすと、同点や逆転しない組合せがある。人が2件を確認して確定する設計なので、この条件が画面に無いのは説明の欠落である。

**直し方。**

1. 単独の感度（現行の `.sens`）の文に、固定条件を必ず付ける。
   - インパクト側: 「否定側の発生可能性を暫定値4に固定した場合、この値が5以下なら判定は肯定側に逆転する。」
   - 発生可能性側: 「否定側のインパクトを暫定値8に固定した場合、いずれの代替値でも判定の向きは変わらない。」
   - 固定条件の側名・値は、データから生成する。手打ちしない。
2. 判定の場面に、**組合せ感度表**を追加する。
   - 行: 否定・発生可能性の値。暫定値と代替値（4 / 5 / 7）。
   - 列: 否定・インパクトの値。暫定値、他方を暫定値に固定したときの逆転境界、その1つ下（8 / 5 / 4）。
   - 各セル: 判定側と点差。同点は「同点」と表示する。
   - 値の集合は保留のデータ（`alts` と現行の境界計算）から作り、セルの値はすべて最終差の計算関数で再計算する。**手打ちの数値は置かない。** 重みは差の符号で決まるので、値を動かしたときは重みも計算し直す（現行の単独感度と同じ扱い）。
   - 保留が3件以上になっても動く形にしておくが、表示は現行の2件でよい。
3. 同点のルールを一行で示す。「同点の場合、エンジンは判定を出さない。人が確認して確定する。」（確定）

**検算。** 他の値を現状のままにすると、組合せ表は次になる（受け入れ基準として使う）。

| 否定・発生可能性 ＼ 否定・インパクト | 8（暫定） | 5 | 4 |
|---|---|---|---|
| 4（暫定） | 否定 3.5点差 | 肯定 1点差 | 肯定 2.5点差 |
| 5 | 否定 4.5点差 | 同点 | 肯定 1.5点差 |
| 7 | 否定 6.5点差 | 否定 2点差 | 否定 0.5点差 |

（肯定の重み反映後合計は 30.5 で固定。否定は 18 ＋ p ＋ 1.5×i。最終差 ＝ 12.5 − p − 1.5×i。）

### 3.2 発言にない情報を解説で補わない

**① 0:32 の解説が、質疑（0:52〜0:57）の情報を先取りしている。**

- 現行: 肯定・立論採点の `why.inh` に「規制が入った後もなお長時間労働が残っている」とある。`SUMCMP.inh.why` にも同じ文がある。
- 立論で聞けるのは「厚労省の2022年調査で9.7%が週60時間超」まで。規制後かどうかの明示的確認は 0:52〜0:57 の質疑。
- 直し方:
  - 0:32 の `why.inh` は「現に起きている長時間労働の報告」として書く。規制との関係には触れない。点数 8 は変えない（8 の根拠は「出典付きで現に起きていること」で足りる）。
  - 0:57 に解説の追記を置く。「質疑で、この数字が規制後のものだと確認された。現状との連続性の評価はこれを含めて 8 のまま。」点数変動イベントは足さない。
  - `SUMCMP.inh.why` の該当文も同じ内容に直す。

**② 2:42 の解説が、雇用7割の数字を「別の資料」と扱っている。**

- 現行: 「インパクト8は下げていない。雇用の7割という別の資料に支えられており……」
- 1:16 の発言に7割という数字はあるが、出典は示されていない。資料の存在を解説側で補ってはいけない。
- 直し方: 「インパクト8は下げていない。この8は 1:16 の『中小企業が労働者のおよそ7割を雇用する』という発言中の数字と価値づけに基づくもので、出典は示されていない。2:42 の攻撃は資料の調査範囲に向けたもので、この数字自体は攻撃されていないため、値はそのまま残る。」
- 否定・立論採点の `why.imp` と、判定の場面の「採点の揺れ」の説明にある「雇用の7割」も、「出典未提示の数字」であることが分かる文にする（3.4 と合わせて直す）。

### 3.3 重みの条件を一意に定め、攻防の点数との役割を分ける

**問題1。** 0.5倍の条件の主語が曖昧で、1.5倍と同じ場面を別の側から述べているようにも読める。

- 直し方: 「総括：観点ごとの比較」の見出し直下に、次の表を常時出す。

| 総括で比較を制した側 | 重み | 意味 |
|---|---|---|
| 立論の差で優位な側が制した | 1.5 | 自分が優位な土俵で比較を示した。差を広げる |
| 立論の差で劣位な側が制した | 0.5 | 相手が優位な土俵で比較を示し返した。差を削る |
| 決着なし | 1.0 | 動かさない |
| 土俵にしない観点 | 1.0 固定 | 比較の対象外 |

- 各観点の行では「優位側」と書かず、側を名指しする。例: 「インパクト：否定が6点優位。**優位の否定**が制した → 1.5」「解決性・不可避性：肯定が1点優位。**優位の肯定**が制した → 1.5」。
- この試合では 0.5 の例が出ない。表の下に一行、「この試合では 0.5 の観点はない。仮に肯定側が総括でインパクトの比較を制していれば、否定の6点優位が3点優位に縮んでいた」と、計算から生成した仮定例を置く（数値は関数で計算する）。

**問題2。** インパクトについて、攻撃成立（2:18）、無応答の落とし（3:32）、総括での1.5倍（4:14）が、同じ未応答を三重に評価しているように見える。

- 直し方: 総括比較ステージのジャッジ発言と、右列の表の下に、役割分離の説明を置く。

> 攻防の点数（立論→攻撃→防御）は、その論点がどれだけ残っているかを表す。重みは、総括でどの土俵に比較を載せたかを表す。重みは**総括の発言だけ**から決め、攻撃や防御の結果からは決めない。インパクトでは、2:18 の攻撃と 3:32 の無応答で点数が 9→4→2 と動き、4:14 の総括で否定がインパクトを比較の軸にし、肯定の総括はその軸に乗らなかったので 1.5 になった。三つの段階の三つの事実であり、同じ事実を三度数えたのではない。

- 併せて、一文を添える。「計算は明快だが、この重み付けが妥当かどうかは計算式だけでは証明できない。重みの根拠となる発言を、時刻で示す。」`SUMCMP.*.src` の参照を、この文の直後に出す。

### 3.4 初期点の基準：段階表の重なりをなくし、否定側インパクト8の対象範囲を明記する

**問題1。** `RUBRIC.scale` の 9（数字と価値づけの両方で支えられている）と 8（規模を示す数字があり、隙間が一つ残る）は、否定側インパクトのように「規模の数字＋価値づけ、ただし出典なし」の場合に両方当てはまる。

- 直し方: 9 と 8 の定義を排他的にする。案:
  - 9: 「被害の大きさを示す数字と価値づけの両方が、**出典付きで**支えられている。プランの対象範囲との対応は述べられていない」
  - 8: 「規模または出発点を示す数字はあるが、**出典が示されていない、または被害の大きさ自体の数字がない**。対象範囲との対応や規模の内訳など、隙間が残る」
  - 他の段階も、上下の段と条件が重ならないか一度見直し、重なる箇所は報告する（実装前）。

**問題2。** 肯定側の全国数値には「300人以上の企業との重なりが述べられていない」ことを織り込んでいる（`why.inh` の「9にしない」理由）のに、否定側の「中小企業の雇用7割」には同じ扱いをしていない。

- 直し方（8 章の補足②で確定済み。詳細はそちらに従う）:
  - 否定・立論採点の `why.imp` に、二つの隙間を明記する。「7割は中小企業全体の数字で出典は示されていない。また、プランが届く300人以上の企業との重なりは述べられていない。賃金低下・人員削減の規模も数字で示されていない。」
  - 判定の場面の「採点の揺れ」の説明に、揺れの原因として「対象範囲との重なりが未提示であること」を加える。この保留は、肯定側と同じ基準を否定側にも当てるための保留でもある、と書く。
  - 点数 8 は変えない。

### 3.5 2:18 の確認状態を表示する

**問題。** 「1万人は脳血管疾患・心疾患による死亡の全体で、労働時間が原因の死者数ではない」という否定側の反論について、資料原文で誤読が確認されたのか、反論が提示されて応答されなかっただけなのかが区別されていない。

- 直し方:
  - 2:18 の解説に確認状態を出す。「資料原文：未確認。エンジンは資料の読み方の正誤を判定していない。点数（9→4）は、反論が提示され、防御で応答されなかったことに基づく。」
  - 判定の場面の内訳表または脚注に、同じ状態を一行で出す。
  - **3件目の保留にはしない（確定）。** 理由: 点数は無応答に基づいて決まっており、原文の確認結果で変わる設計になっていない。この理由も画面に書く。二種類の未確認を区別して示すこと。詳細は 8 章の補足③に従う。

### 3.6 3:38 の ＋2 の根拠を二つに分ける

**問題。** 部分回復 ＋2 が、「肯定側の再配置の主張に資料がない」への反論によるものか、「否定側の資料が300人以上の企業を対象にしている」ことの証明によるものかが読めない。

- 直し方: 3:38 の解説を次の二つに分けて書く。
  - 反論として成立したもの: 質疑（2:54）で引き出した「再配置に資料がない」という点。これが部分回復 ＋2 の根拠であり、＋2 はこれだけによる。
  - 未解決のまま残るもの: 否定側の資料が300人以上の企業を対象にしているかどうか。新しい資料も、立論資料の再提示もなかったため証明されていない。値は暫定4で、保留は続く。

### 3.7 3:14 の台詞と 3:38 の解説を整合させる

**問題。** 3:14 の準備時間で否定側は「新しい資料は出せないから、言い直しになるな」と言うが、3:38 の解説は「ディフェンスで新しいデメリットを足すことは禁止されているが、既存の議論を資料で補強することは可能だった」と説明している。台詞が規則の誤解に見える。

- 直し方: 3:14 の台詞を、規則ではなく手元の材料の問題に変える。案: 「こっちは、再配置の資料がないって点を突く。自分の資料の範囲は、立論で読んだ報告をもう一度引けば示せるが、読み返す時間がない。言い直しになるな。」
- 3:38 の解説に一文を足す。「立論で読んだ資料をもう一度引いて調査範囲を示す選択肢は、準備時間（3:14）で認識されていたが、見送られた。」
- 準備時間の台詞は採点に使わない（脚注のとおり）ので、点数には影響しない。

## 4. 表示に関わる修正

### 4.1 暫定と保留の二段階表示（2:42 から印を付ける）

- 現行は 2:42 の解説で「同一性を前提にした暫定値」と説明しているのに、点数表の保留印は 3:38 から。

  - 凡例（`#key`）に両方の印を加える。

### 4.2 判定付近に「要確認2件」の導線をまとめる

- 判定の場面の冒頭（暫定判定の直後）に、要確認項目の一覧を置く。件数はデータから数える。
  - 各行: 側・観点・暫定値・保留の種別・単独感度へのリンク・組合せ表へのリンク。
  - 3.5 の「資料原文：未確認」は、保留とは別の見出し（「参考：確認されていない事実」など）で同じ枠に並べる。
- 右列の判定の内訳表からも、組合せ表へ1クリックで移動できるようにする。

### 4.3 採点の揺れの根拠を表示する

- 「複数回採点したところ、この観点だけ値が散らばり、閾値を超えた」と説明しているが、回数・各回の値・閾値が画面にない。
- 直し方: 保留のデータに `runs`（各回の値の配列）と `threshold`（範囲がこの値以上で保留）を持たせ、判定の場面と単独感度の枠に「採点 n 回：値 …、範囲 …、閾値 …」と出す。他の観点は範囲が閾値未満だったことも一行で示す（値は持たせず、文だけでよい）。
- 値はデモ用の仮値でよい（確定）。ただし画面に「デモ用の値（未実測）」と明記し、データの場所を報告する。詳細は 8 章の補足④に従う。

### 4.4 解説の構造化

- 点数変動を伴う解説（8件）と判定の解説を、次の4区分で表示する。
  1. 判断（何をどう分類したか、一〜二文）
  2. 根拠（対応する発言の時刻と内容）
  3. 点数の変更（観点、前→後、段階表の該当行）
  4. 未確認事項（保留・確認状態。無ければ「なし」）
- データ側は、現行の `body` 配列を残したまま、任意の構造化フィールド（例: `judg` / `basis` / `change` / `open`）を足す形でよい。フィールドがあれば区分表示、無ければ現行どおり段落表示。
- 文は短くする。既存の段落から重複を削り、3 章で直した内容を反映する。

### 4.5 バージョン表記の削除と、判定への導線

- 利用者向けの文（`<title>`、解説、ジャッジ発言、右列）から「v19」などの内部バージョン表記を消す。バージョンは HTML コメントと `<meta name="version">` にだけ残す。
- ステージ帯 `#chips`:
  - 現在のステージが常に見えるよう、移動時に該当チップを `scrollIntoView` する。
  - 幅が十分なら折り返して2段で全表示する（横スクロール不要）。折り返せない幅では、帯の右端に「判定へ」ボタンを固定表示する。
- 主要場面（`#qnav`）の「総括比較」「判定」は現状維持。
- 左の吹き出し・右列・ページ全体の3つのスクロール領域について、長い解説を表示するときに右列の該当解説の先頭へ自動スクロールする（現行にあれば維持）。

## 8. 確定済みの判断（変更しないこと）

以下は着手前に確定した。実装中にこれを覆す提案はしないこと。異論がある場合は実装を止めて報告する。

| # | 論点 | 確定 |
|---|---|---|
| ① | 同点のルール（3.1） | エンジンは判定を出さず、人が確定する。組合せ表の同点セルにこの旨を示す |
| ② | 否定側インパクト8の対称性（3.4） | **8 を維持する。** 隙間を明記し、既に発生可能性で減点済みであることを示す（下の補足参照） |
| ③ | 2:18 を保留にするか（3.5） | **保留にしない。** 確認状態のみ表示する（下の補足参照） |
| ④ | 採点の揺れの実測値（4.3） | 仮値で実装し、データの場所を報告する。**画面に「デモ用の値」と明記する**（下の補足参照） |
| ⑤ | 3:14 の台詞（3.7） | 3.7 の案のとおり「読み返す時間がない」に変更する |

### 補足②：否定側インパクト8を維持する理由（3.4 に反映すること）

現行デモは、否定側の対象範囲の問題を**既に発生可能性で減点している**。否定・立論採点の `why.prob` に「デメリットは中小規模の企業の話だが、プランの対象は従業員300人以上であり、規定2.1.2により実際に提示されたプランから生じることを証明しなければならない。7。」とある。

つまり非対称なのは「否定側だけ対象範囲を見逃している」ことではなく、**肯定側は現状との連続性・解決性で、否定側は発生可能性で減点している**という、採点する観点の違いである。レビューはインパクトの列だけを見たため、否定側が無傷に見えた。

したがって 3.4 の問題2 は、次のように直す。

- 否定・立論採点の `why.imp` に、8 に残る隙間を明記する。「7割は中小企業全体の数字で、出典は示されていない。賃金低下や人員削減の規模も数字で示されていない。」
- 同じ `why.imp` に、対象範囲の扱いを一行で示す。「プランが届く300人以上の企業との重なりが述べられていない点は、発生可能性の採点（7）で既に織り込んでいる。インパクトでは重ねて減点しない。」
- 判定の場面の「採点の揺れ」の説明に、揺れの原因として「7割の出典が示されていないこと」を加える。
- **点数 8 は変えない。** 発生可能性 7 も変えない。

なお「対象範囲との対応をどの観点で採点するか」を採点基準そのものとして原則化する案は、肯定側の `why.inh`（9にしない理由が対象範囲になっている）の書き換えを伴うため、v20 では扱わない。**9 章に持ち越す。**

### 補足③：2:18 を保留にしない理由（3.5 に反映すること）

保留は「人が確認すると値が変わる項目」に付ける印である。2:18 の 9→4 は、否定側の反論が提示され、肯定側が防御で応答しなかったことに基づく分類（数値の側の崩壊、到達点4）であり、**資料原文を確認して否定側の読み方が誤りだと分かっても、応答がなかった事実は変わらないので点数は動かない。** 動かないものに保留を付けると、印の意味が壊れる。

そのうえで、この区別自体を画面に出す。3.5 の表示に次の趣旨を含めること。

> 未確認には二種類ある。人が確認すると値が変わるもの（保留2件）と、確認しても値が変わらないもの（この資料の読み方）である。エンジンは資料の読み方の正誤を判定していない。ここでの点数は、反論が提示され、防御で応答されなかったことに基づく。

4.2 の要確認枠でも、保留2件とは別の見出しで並べる（枠は同じ、扱いは別）。

### 補足④：採点の揺れの仮値の表示

実測前なので仮値で実装してよいが、**実測値であるかのように見せてはならない。** 表示に「デモ用の値（未実測）」と明記し、`runs` / `threshold` を置いたデータの場所を報告すること。発言にない情報を解説で補わないという 3.2 の原則は、エンジン自身の内部数値についても同じである。
