## 1. 背景

v19／v20 は、観点ごとの差 `d_k` に重み `w_k` を掛け、それを**足し合わせて**最終差を出している（`Σ d_k × w_k`）。この形は説明しやすく、v19 の狙い（総括は点数を足さず重みだけを動かす）を実現できていた。

しかし HEnDA の公式 Judge Sheet が定める判定軸は、次の形である。

```
Probability（蓋然性） × Value / Impact（価値・重要性） ＝ Strength（議論の強さ）
```

つまり判定は**積**である。そして立論の構成（`Present Situation → Effect → Importance`）のうち、**Effect は独立した判定軸ではなく Probability を決める下位要素**である。「プランを実施すると本当にその変化が起こるのか」が崩れれば Probability が下がる、という関係にある。旧来のジャッジ基準でも、Probability は「メリットが確実に得られるか」を見るもので、Attack 後に回復できなければゼロにもなり得るとされている。

現行の5観点を横並びに加算する設計は、この構造を反映していない。具体的な不都合は次のとおり。

- **Probability が崩れても Impact が残れば合計が残る。** 現行データでは否定側の発生可能性が 7→2 まで落ちているのに、インパクト8 がそのまま合計を支えている。積であれば、発生可能性が 2 まで崩れた時点でその Disadvantage の Strength は大きく落ちるはずである
- **「回復できなければゼロにもなり得る」が表現できない。** 和では、ある観点が 1 まで落ちても他の観点の値がそのまま残る
- インパクト10・発生可能性1 の議論が、インパクト5・発生可能性8 の議論に勝ちうる。実際の判定感覚と合わない

v21 は、**判定の集計を積に変え、公式 Judge Sheet の構造に合わせる版**である。観点の名前・表示の骨格・攻防の点数変動は動かさない。**変えるのは集計の仕方だけ**である。

### 1b. この版の位置づけ

v21 は**積モデルの振る舞いを実物で確かめるための検証版**である。応募物としての改善ではない。したがって次の制約が最優先で適用される。

- **`main` は絶対に触らない。** 公開版（`debate-judge-demo.vercel.app`）は現在、コンテストの審査に使われている

- プレビューと現行 main を二つのタブで並べ、同じ試合データで結果がどう変わるかを比較できる状態にする

## 3. 判定モデルの変更

### 3.1 観点を Probability 側と Impact 側に振り分ける 【最優先】

現行の5観点を、公式 Judge Sheet の二つの軸に対応づける。**観点そのものは残し、どちらの軸に属するかの属性を足す。**

| 観点 | 属する軸 | 理由 |
|---|---|---|
| 現状との連続性 | Probability | `Present Situation`。現に問題が存在するか |
| 発生可能性 | Probability | `Effect` の一部。プランから実際に生じるか |
| 解決性・不可避性 | Probability | `Effect` の一部。どこまで解決／回避できるか |
| インパクト | Impact | `Importance`。被害・利益の大きさと価値 |
| 資料の裏づけ | **どちらでもない**（3.2 参照） | 独立軸ではなく、他の観点を支える要素 |

`DIMS` の各要素に `axis` を足す（`'P'` / `'I'` / `'evd'`）。

### 3.2 資料の裏づけの扱い

**現行の問題**: 資料の裏づけは独立観点として加算されているが、`SUMCMP.evd.why` 自身が「射程をめぐる指摘は発生可能性の土俵で扱う」と書いており、**同じ指摘で二度減点している**（2:04 と 2:42 はいずれも発生可能性と資料の裏づけの両方を削っている）。規定 3.1 も「証拠資料を引用しているかいなかだけで試合の勝ち負けが決まるわけではない」「資料を引用したとしても質の低い資料の場合、効果はありません」と述べ、資料を独立の評価対象としていない。

**v21 での扱い（確定・8 章 ①）**: **資料の裏づけを Strength の計算から外す。** ただし画面からは消さない。

- 点数表には従来どおり表示し、攻防による値の変動も記録する（何が起きたかの記録としては有用）
- Strength の計算には含めない。「記録用・計算外」と画面に明示する
- `SUMCMP.evd` の `arena:false` は維持

本来は各観点に織り込むべきだが、それには立論の採点をやり直す必要があり、2 章の「入力値を動かさない」と衝突する。v21 では計算から外すにとどめ、織り込みは 9 章に送る。

### 3.3 Strength の計算

**Probability の合成: 属する観点の最小値を取る。**

```
P_side = min(現状との連続性, 発生可能性, 解決性・不可避性)
```

規定 2.1.1.3 は三論点を並列に課しており、どれかが強ければ他を補える、とは書いていない。証明されていない環があれば、そこで鎖は切れる。現状に問題が無ければ効果があっても意味がなく、逆も同じ。

**min で捨てた側の値も記録に残すこと。** 防御で回復すれば効く環が入れ替わる。どの観点が Probability を決めているかは、表示（4.1）でも感度分析でも必要になる。

**Strength の計算:**

```
Strength_side = P_side × Impact_side
```

**重みの適用:**

Strength が積であるため、`P` に重みを掛けても `Impact` に重みを掛けても Strength への効果は同じ倍率になる。したがって**重みは論点単位で Strength に掛ける**。

```
重み付き Strength_side = Strength_side × W_side
```

`W_side` は、その側の観点にかかった重みから決める。現行の `SUMCMP` は観点ごとに `c` を持つので、**その側にとって 1.5 になった観点があれば 1.5、0.5 になった観点があれば 0.5、いずれも無ければ 1.0** とする。両方が生じる場合は積を取る（1.5 × 0.5 = 0.75）。

現行データでは、インパクトを否定側が制して 1.5、解決性・不可避性を肯定側が制して 1.5 なので、`W_aff = 1.5`（解決性）、`W_neg = 1.5`（インパクト）になる。

**最終判定:**

```
肯定側合計 = 重み付き Strength_ADV
否定側合計 = 重み付き Strength_DIS
合計が大きい側の勝ち。等しい場合は 9 章（v21 では引き分け表示のままでよい）
```

### 3.4 解説の修正（最小限）

判定モデルが変わるので、モデルを説明している箇所だけ直す。**台詞や攻防の解説は触らない。**

- **総括比較ステージ**（`kind:'sumcmp'`）の `body`: 「重みは点数ではなく差に掛ける倍率」という説明を、「重みは論点の Strength に掛ける倍率」に改める。差に掛ける説明は和モデルのものなので、そのままでは誤りになる
- **判定**（`kind:'verdict'`）の `say` / `judg` / `body`: 素点と重み反映後の数値を、新しい計算に合わせる。**数値はすべて計算結果から生成し、手打ちしない**
- 判定の吹き出しに、**Probability をどの観点が決めているか**を両側について一行で出す（例「否定側の Probability は発生可能性 2 が決めている。現状との連続性 6・解決性 6 はそれより高い」）

## 4. 表示の変更

### 4.1 判定の内訳表

現行の「観点／立論の差／重み／効いた差／合計」を、積モデルに合わせて作り直す。**列見出しは記号でなく日本語で書く**（v19 §4.2 の原則を継承）。

構成:

1. **軸ごとの値**（両側）
   - Probability: 属する3観点の値を並べ、**最小値に印を付ける**。「この値が Probability を決めている」と分かる形にする
   - Impact: インパクトの値
2. **Strength の計算**: `P × Impact = Strength` を両側について式のまま出す
3. **重みの適用**: `Strength × W = 重み付き Strength`。`W` がその値になった理由（どの観点で誰が制したか）を併記
4. **結論**: 両側の合計と、どちらが何点差で勝ったか

**表の先頭に結論を置く**（v19 §4.2 の原則）。表が伸びて下端が見切れても、結論だけは読めるようにする。

**資料の裏づけは表の外に、「記録用・計算外」として別掲する**（3.2）。

### 4.2 点数表

- 資料の裏づけの行に「計算外」の印を付ける
- Probability に属する3観点のうち、**最小値になっている観点に印を付ける**（どれが効いているかが一目で分かるように）
- 既存の「暫定」「保留」の印、推移の行はそのまま

### 4.3 感度分析

`holdSens()` / `comboGrid()` は計算関数を差し替えるだけで動くはずだが、**積モデルでは感度の出方が和より鋭くなる**。Probability 側の変動は Impact 倍で効くため、保留の値を1動かしたときの最終差の変化が大きくなる。

- 逆転境界の計算はそのまま（計算関数を新しいものに差し替える）
- 組合せ感度表もそのまま
- **v20 の検算表（3.1 の表）は使えない。** 和モデルの数値なので、積では一致しない。新しい値は実装後に画面から読み取って報告すること（6 章）

### 4.4 モデルの説明枠

右列の「総括：観点ごとの比較」の上に、判定モデルを一枚で示す枠を常時出す。

```
Probability（現状との連続性・発生可能性・解決性の最小値） × Impact（インパクト） = Strength
Strength × 重み = その論点の最終値
資料の裏づけは記録用（計算には含めない）
```

公式 Judge Sheet の形に基づくことを一行添える。

## 6. 受け入れ基準

1. 判定の内訳表に、両側の `P × Impact = Strength` が式のまま出る
2. Probability を決めている観点（最小値）に印が付き、点数表と内訳表の両方で確認できる
3. 資料の裏づけが Strength の計算に含まれておらず、「計算外」と明示されている
4. 8件の点数変動が v20 と同じ時刻・同じ値・同じ分類で出る（**入力値は変わっていない**）
5. 重みが 1.5 / 1.0 / 0.5 の決め方どおりに適用され、その理由が画面に出る
6. 総括比較と判定の解説から、「差に掛ける倍率」という和モデルの説明が消えている（`grep` で確認）
7. 判定の吹き出しに、両側の Probability をどの観点が決めているかが出る
8. 保留の感度分析が動き、逆転境界が計算される
9. ブラウザのコンソールに、アプリ由来のエラーが出ない
10. 冒頭から判定まで通しで再生でき、左右キー・Shift＋左右・主要場面・時刻リンク・採点基準の開閉が動く
11. **`main` に一切コミットされていない。プレビュー URL で確認している**

**報告してほしい数値**（実装後、画面から読み取って報告すること。コードを読んだだけの報告は不可）:

- 両側の Probability とそれを決めた観点
- 両側の Strength（重み適用前）
- 両側の重み付き Strength と、最終的な勝敗・点差
- 保留2件それぞれの逆転境界（v20 の値と比べてどう変わったか）

**v20 との比較**: 現行 main と並べて、同じ試合で判定がどう変わったかを一言で報告すること。向きが変わったか、点差がどれだけ開いた／縮んだか。

## 8. 確定済みの判断（変更しないこと）

| # | 論点 | 確定 |
|---|---|---|
| ① | 資料の裏づけ（3.2） | **計算から外す。表示は残し「計算外」と明示。** 各観点への織り込みは 9 章 |
| ② | Probability の合成（3.3） | **最小値を取る。** 積や加重平均にしない。捨てた側の値も記録に残す |
| ③ | 重みの適用単位（3.3） | **論点単位で Strength に掛ける。** 積では軸ごとに分けても効果が同じため |
| ④ | 値域（3.3） | **現行の 1〜10 のまま。** 0〜1 の係数化は 9 章。v21 は集計の形だけを変える |
| ⑤ | 同点の扱い | **v21 では扱わない。** 現行の引き分け表示のまま。規定 4.2 の推定は 9 章 |
| ⑥ | 観点の名前 | **変えない。** 三論点への組み替えは 9 章 |

### 補足：値域を現行のままにする理由

積モデルでは値域の取り方が結果に直接効く。1〜10 × 1〜10 なら Strength は 1〜100 になり、和モデルの 50 点満点とは桁が変わる。Probability を 0〜1 の係数として扱えば「回復できなければゼロ」がそのまま表現でき、そちらが本来は望ましい。

しかし係数化には立論の採点基準そのものの作り直しが伴い、2 章の「入力値を動かさない」と衝突する。**v21 の目的は積モデルの振る舞いを見ることであり、値域の最適化ではない。** まず現行の値域で動かし、その結果を見てから値域を決める。

## 9. v21 では扱わない（次版以降／analyzer 側で扱う）

実装中にこれらに手を出さないこと。気づいた点は報告のみ。

- **三論点（Present Situation / Effect / Importance）への組み替え。** 5観点を規定の構成に作り直す改修。データ構造・表示・感度分析まで波及するため、analyzer 側で行う
- **資料の裏づけを各観点に織り込む。** 立論の採点をやり直す必要がある
- **値域の見直し**（Probability の 0〜1 係数化を含む）
- **同点時の扱い。** 規定 4.2 は引き分けを認めず、優劣がつけられない場合は推定により否定側とする。v21 では現行の引き分け表示のまま
- **ディフェンス・総括での資料の働きの判定。** 規定 4.2.2 は、相手の証明に対する新しいアタックの証拠資料をディフェンス・総括で出すことを「新しい議論」として無視する。現行の「全回復＝資料を伴って応答」の定義はこれを区別していないが、修正には防御分類の追加が要る
- **防御分類への「新規アタックとして無視」の追加**
- **総括の比較主張の適格性判定**
- 採点の揺れの実測
- スマートフォン表示と音声の検証
- **`main` へのマージ**（審査終了後に別途判断）
